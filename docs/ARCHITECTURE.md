# 아키텍처 가이드

## 파이프라인 요약

| 모듈            | 트리거                                     | 출력 대상                    |
| --------------- | ------------------------------------------- | ---------------------------- |
| Light Review    | 보호되지 않은 브랜치에 대한 `push`         | 커밋 코멘트                  |
| Deep Review     | `pull_request` 이벤트(열림, 업데이트 등)    | PR 코멘트                    |
| Documentation   | 기본 브랜치로 머지된 후 `push`             | `docs/` 아래 마크다운        |
| Issue Up        | 기본 브랜치로 머지된 후 `push`             | GitHub Issue(필요 시)        |

각 모듈은 컴포지트 액션으로 구현되어 GitHub 호스티드 러너와 셀프 호스티드 러너에서 동일하게 재사용됩니다.

## 실행 흐름

1. **Codex CLI 준비**  
   `setup-codex-cli` 컴포지트 액션이 고정 버전의 Codex CLI를 설치하고, 캐시를 복원합니다.

2. **모듈별 프롬프트 실행**  
   모듈 액션이 대응되는 프롬프트 파일을 읽어 지정된 모델로 Codex CLI를 호출하고, 생성된 리포트를 디스크에 저장합니다.

3. **결과 게시**  
   워크플로는 생성된 리포트를 `gh` CLI에 전달해 커밋/PR/이슈 코멘트를 작성합니다. 문서화 결과는 워크스페이스에 커밋하여 아티팩트 업로드 또는 저장소에 직접 푸시할 수 있습니다.

## 프롬프트 관리

- 프롬프트는 모두 `prompts/` 디렉터리에 있습니다.
- 각 워크플로는 액션 입력값으로 프롬프트 경로를 받아 수정자가 YAML을 손대지 않고도 리뷰 스타일을 바꿀 수 있습니다.
- 프롬프트 버전 관리나 메타데이터 표시를 통해 변경 히스토리를 추적하는 것을 고려해 주세요.

## 러너별 고려 사항

- **`ubuntu-latest`**: 기본 러너로 GitHub CLI가 이미 포함되어 있습니다. Codex CLI는 Python/pip으로 설치합니다.
- **셀프 호스티드**: 사전에 `gh` CLI 설치 및 인증이 필요하며, 컴포지트 액션은 Linux 호환 셸을 가정합니다.

## 확장 아이디어

- Codex CLI의 표준 출력/에러를 워크스페이스 아티팩트로 수집해 텔레메트리를 남길 수 있습니다.
- 필요 시 `strategy matrix`를 활용해 Light/Deep 리뷰를 병렬로 실행할 수 있습니다.
- 리포트 형식을 고도화하려면 `templates/` 디렉터리에 코멘트 템플릿을 분리하는 방안을 검토하세요.
